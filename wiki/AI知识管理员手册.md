
> 本手册规定 AI 如何整理、查询和维护 Obsidian Wiki。
> Wiki 的目标不是保存所有资料，而是将有价值的信息转化为：

- **可理解的知识**：经过整理，能够清楚解释一个概念、原理或问题。
    
- **可复用的知识**：能够应用于其他问题、项目或实际场景。
    
- **可关联的知识**：能够与 Wiki 中已有知识建立联系。
    
- **可信赖的知识**：能够追溯来源，区分事实、观点和推断。
    
- **可持续发展的知识**：允许补充、修正、合并和更新。
    
原则：**优先提高知识质量和可用性，而不是追求笔记数量、目录数量或形式上的完整，结构简单、内容可靠、长期可维护。**
> 
## 1. 目录结构

```text
wiki/
├── index.md          # 文章索引（导航 + 一句话摘要）
├── log.md            # 重要操作记录（只追加）
├── AI与大模型/  编程开发/  金融投资/  管理与方法论/  工具软件/
raw/                  # 原始资料，默认不可修改、覆盖或删除
└── .manifest.json    # 原始资料与文章的映射
```

约定：

- 可在主题目录下建子目录，但不为单篇文章新建目录。
- 不擅自改变目录结构，不新增管理文件。
- 内部链接用 `[[文章标题]]`；日期用操作当天日期。

## 2. 原始资料

- 录入素材时，先确认来源可访问，再按类型处理：
    - 本地文件：纯文本类（md、txt）直接拷贝至 `raw/`；DOCX 使用Pandoc转为 Markdown 文件存入 `raw/`，其他无法直接转换的文件，解析后转成 Markdown 文件，存入 `raw/`。
    - 网址：解析网页正文为可读的 Markdown 文本，存入 `raw/` 并在文末记录来源链接。
- 无法读取的内容说明原因，不得谎称原文没有。

## 3. 笔记组织原则

**默认一份资料整理成一篇笔记，同主题内容优先整合进已有文章。**

文章按需包含：资料来源、核心内容、知识提炼、相关实体、分析思考（不要求全有）。

**何时新建文章：**

- 同一资料重复录入 → 更新已有文章。
- 不同资料同主题 → 补充已有文章，保留各自来源和观点。
- 独立新主题 → 在合适目录下新建。
- 已形成可跨文章复用的完整概念 → 可单独建页并链接。
- 来源观点冲突 → 保留各自说法，不强行合并。

保留有长期价值的内容（原理、步骤、数据、案例），精简重复背景。

## 4. 知识录入与整理

收到新资料后，按照以下原则处理：

1. **阅读与筛选**：完整阅读资料，提取核心概念、原理、方法、经验和重要事实。只保留具有长期参考、学习或应用价值的内容，不必收录重复、临时或无实质价值的信息。
    
2. **检索与去重**：创建笔记前检查 Wiki 中的相关内容，优先补充、更新或合并已有笔记，避免重复创建。发现信息冲突时，保留差异并核实来源。
    
3. **整理与写作**：根据知识内容组织笔记，不强制拆分。一篇笔记可以包含多个相关知识点。使用清晰的标题，先说明核心结论，再解释原理、方法和必要的示例，同时保留重要细节、适用条件及局限性。
    
4. **建立关联**：使用 Obsidian 双向链接 `[[笔记名称]]` 连接真正相关的知识，如概念与原理、方法与案例、理论与实践等。不强行增加链接。
    
5. **保存与检查**：保存到合适的位置，检查内容、文件名和内部链接，避免重复、错误及未经证实的信息，不破坏原始资料。
    
## 5. 笔记写作与来源规范

以清晰、准确、易于理解和复用为目标，不强制使用固定模板。

根据内容需要组织以下部分：

- **来源**：记录原始资料及必要的定位信息。

- **核心结论**：说明最重要的知识。
    
- **核心内容**：解释概念、原理、机制或方法。
    
- **示例与应用**：提供必要的案例或实践说明。
    
- **局限与注意事项**：记录适用条件、风险和争议。
    
- **相关知识**：链接已有的相关笔记。
    
来源应尽可能可追溯，例如网页链接、论文 DOI、书籍章节、PDF 页码、视频时间戳等。

整理时区分事实、观点、推断和实践经验。重要结论应有依据，不得将推测写成事实；存在争议或不同解释时，应保留其差异及来源。

**核心要求：既要保留有价值的信息，也要让整理后的知识更容易理解、检索和复用。**

## 6. 原始资料映射

`raw/.manifest.json` 记录映射，不另建来源账本：
```json
{
  "version": 1,
  "items": {
    "raw/视频/示例.mp4": {
      "source_type": "video",
      "origin": "用户提供",
      "wiki_articles": ["wiki/AI与大模型/示例主题.md"],
      "ingested_at": "2026-11-04"
    }
  }
}
```

- 重复整理同一资料时更新原记录；仅新增资料或路径变化时更新 manifest。

## 7. 常用操作

### Ingest（录入）

触发：用户明确要求收录、整理资料时。

1. 确认素材存在并读取；查看 `index.md` 和相关文章查重；检查 manifest。
2. 决定更新旧文或新建文章；更新时只改相关内容，保护原有观点、来源和链接。
3. 保留原始资料，必要时提取附件；更新 manifest。
4. 文章增删改时更新 `index.md`；重要操作追加到 `log.md`。
5. 完成后检查保存结果、来源路径和链接.

### Query（查询）

触发：用户询问、总结或比较 Wiki 已有知识时。

- 通过 `index.md` 定位文章，只读所需内容，优先依据 Wiki 回答。
- 用模型自身知识补充时标注「外部补充」；来源冲突或未核实的如实说明。
- 默认只回答，不改文件、不更新索引、不记日志。用户要求保存结果时，按正常录入规则整理成笔记。

### Lint（检查）

**触发条件：** 用户明确要求检查或整理 Wiki 时执行。

**检查范围：**

- `raw/.manifest.json`：检查原始资料记录是否与实际文件一致。
- `wiki/index.md`：检查 Wiki 文章是否存在、是否漏收录。
- `wiki/log.md`：检查 Wiki 更新记录是否完整。
- 检查 Wiki 是否存在重复内容、来源缺失或内容冲突。
    
**处理规则：**

1. **补充遗漏记录**：实际存在的原始资料或 Wiki 文章，如果没有对应记录，应补充到 Manifest 或 Index。
2. **双向缺失**：Manifest 中记录的原始资料和对应 Wiki 文章都不存在，删除无效记录。
3. **单边缺失**：原始资料或 Wiki 文章只有一方不存在时，暂不删除、不自动修复，标记为待核实。
4. **重复内容**：发现重复文章时，先判断是否可以合并，保留有价值的内容和来源。
5. **更新日志**：仅记录实际发生的新增、修改、合并和删除操作。
    
**处理原则：** 优先修复记录，谨慎处理文件；未经确认，不删除原始资料和有价值的 Wiki 内容。

## 8. 索引、日志与总览

- **index.md**：每篇文章一行 `- [[标题]] — 一句话说明`，只导航不存正文；同名文章用完整路径链接。
- **log.md**：只追加，格式：`- **YYYY-MM-DD** · Ingest — 整理了某主题（[[文章]]）`；不记普通查询和小修改。

## 9. 通用约定

- 内部链接确保目标存在；非 Markdown 文件用正确的附件引用或路径。
- 有 `Updated` 字段时，仅在正文确实修改后更新。
- 移动原始资料须经用户批准：先查目标路径防覆盖，移动后验证文件并同步 manifest 和引用。
- 操作中断或不确定上次结果时，先查文件实际状态，只补齐未完成部分。
- 不确定归属或拆分时，选文件最少、结构最简单的方案。

## 10. 核心原则

1. 先查重，再创建。
2. 一份资料一篇笔记。
3. 保留来源，不把推断写成事实。
4. 更新文章时保护已有内容。
5. 原始资料不随意修改。
6. 只更新受影响的文件。
7. 不为流程而流程，不建无价值的管理文件。
8. 无法确认的明确说明，不猜测、不伪造完成状态。
